# ADR 0006: User-operated CodeBuddy login terminal

Date: 2026-11-16. Status: development implementation; authenticated browser completion remains a manual check.

The owner requested an in-app login flow showing interactive CLI output and a verification URL, then requested a mature terminal component after trying the initial text/buttons UI. CodeBuddy's documented interactive login uses arrow-key choices and browser authentication. The Worker hosts a short-lived Windows ConPTY session within the existing Windows 10 build 19041 minimum. WPF embeds locally bundled xterm.js 6.0.0/addon-fit 0.11.0 through Microsoft.Web.WebView2 1.0.4314.35; no local HTTP gateway or CDN is used. Microsoft Edge WebView2 Runtime is a separate prerequisite, with the original basic text controls as fallback.

The Agent settings button opens an owned WPF login window. An explicit start launches the saved CodeBuddy executable or Node.js entry with `/login`, empty tools/MCP/settings sources, hooks disabled and session persistence disabled in a fresh directory. It receives no OCR/session context. The user operates the menu and browser; Glimpse neither handles passwords nor interprets exit code 0 as successful authentication. A successful generated result is the acceptance check after closing the terminal and reviewing context again.

The Worker owns the native process and a kill-on-close Job Object. Current-user named-pipe operations start/read/input/resize/stop a UUID-scoped login session. A bounded 64KiB raw VT tail with absolute offsets feeds xterm; its keyboard/status responses return to ConPTY. Resize is bounded to 20–240 columns and 5–100 rows. Generation and configuration changes are excluded while login is open; previous previews are invalidated. A separate bounded text parser reconstructs wrapped HTTP(S) verification links; arbitrary URI schemes and embedded credentials are rejected. Transcript-bearing replies are excluded from the ordinary reply cache. There is no terminal transcript, URL or input persistence in SQLite or logs. Diagnostic string representations expose lengths only. The login window is excluded from capture before enabling start. CLI owns its saved account credentials.

The WebView uses a fresh temporary InPrivate profile, a single mapped local origin, strict local-resource/content restrictions and a small message allowlist for input/resize/copy/paste. External navigation, new windows and downloads are blocked. The host explicitly opens user-selected verification links in the default browser; terminal output is parsed by xterm rather than inserted as HTML. On close it clears display data and attempts removal of the guarded temporary profile after browser exit. A slow browser/file lock can leave a temporary profile directory; no session transcript is intentionally saved there.

Native startup uses `STARTF_USESTDHANDLES` with null standard handles so inherited redirected parent handles do not override ConPTY. An on-device synthetic child caught this: before the fix it reported redirected input and `Console.ReadKey` failed; afterward it sees a real terminal. Native and IPC probes verify input, split/wrapped URLs, natural exit, explicit stop, pipe-close cleanup and heartbeat responsiveness. The offline WPF probe covers polling, links/copy, and close-during-start cleanup. These tests launch only a synthetic child and never initiate account authentication.

The mature terminal provides direct keyboard interaction, VT cursor/color handling, selection, copy/paste, font scaling and resizing. Closing it terminates its owned CLI tree. Existing browser processes are not in this job; a newly launched browser/helper still owned by the CLI may also terminate. Account verification is manual; enterprise login and broader CLI-version variants remain open. After the owner logged in, real default-model/MiMo generation, cancellation and card copying passed. The remaining Reader acceptance gates are unchanged.

Model discovery is a separate bounded CLI ACP process: initialize, blank ephemeral session/new, project only available model IDs/names and current model ID, then stop. It offers no client filesystem/terminal capabilities, sends no model prompt and consumes no inference. The UI automatically refreshes for a saved selected CLI and after login closes, preserving typed/configured model text until the user saves a selection. An unavailable catalog permits manually entered IDs; a current default absent from the returned list is not assumed invalid.
